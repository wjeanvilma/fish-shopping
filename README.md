# Fish Shopping

Fully 3D fishing-to-market business sim. The governing spec is
`Fish_Shopping_Full_Game_Blueprint.pdf` (v1.0, 2026-11-05). This repository holds both
clients and the contract they share:

* `app/` + `game-core/`: Android (Kotlin, Jetpack Compose, Filament)
* `web/`: desktop and touch browsers (TypeScript, React, Three.js / WebGL 2)
* `shared/`: content, schema, parity fixtures, design tokens and 3D assets used by both

## Layout

```
shared/                     Cross-platform contract (blueprint "Shared rules and parity")
  content/content-pack.json   Species, products, recipes, machines, upgrades, quests, harbor layout
  schema/                     JSON Schema for the content pack (web validates with it)
  fixtures/                   Parity fixtures both clients must reproduce exactly
    prng-vectors.json           Mulberry32 test vectors (generated by an independent JS implementation)
    starter-line.json           5 min of scripted play: seed + commands + expected canonical state
    snapshot-starter-line-t2500.json  Full save at tick 2500; both clients must encode it byte-for-byte
    legacy/                     Older-schema saves; both clients must migrate them
  tokens/design-tokens.json   Colours, sizes, type scale for Compose and CSS
  assets/models/              GLB scenes (blockout generated from the content pack)
  tools/generate_blockout.py  Regenerates the blockout GLB (layout, item-stack slots, customer pool)

game-core/                  Pure Kotlin simulation. No Android, Compose or Filament.
  sim/          Fixed 20 Hz step, update order, commands/events, state, SimView, PRNG, safe math
  content/      Content model, path-precise JSON loader, cross-reference validator
  inventory/    Capacity-in-carry-units inventories, reservations, transfer rule, invariants
  world/        Ground-plane movement + collision, zone detection, automatic station transfers
  fishing/      Zone stock, weighted species, catch timers
  production/   Machine state machine, batch commit-once semantics, output blocking
  customers/    Spawn, queue, stock reservation, checkout, payment with sale IDs, abandonment
  progression/  Upgrades (validated, idempotent by request ID), quests, tutorial
  persistence/  Versioned + checksummed snapshots; resumes in-progress batches exactly
  workers/      Types only - automation is phase 3

app/                        Android shell
  game/GameViewModel   Runs the sim on one thread, publishes SimView, saves checkpoints
  game/CameraRig       Follow-camera constants + screen->world input mapping
  render/              Filament engine, gltfio scene loading, Choreographer frame loop,
                       Presenters.kt (item stacks + customer crowd, mirrors web presenters.ts)
  ui/hud/              Compose HUD: coins, objective, joystick, station card, bag, upgrades
  persistence/         Latest + previous atomic save slots

web/
  src/engine/   Pure TypeScript port of game-core (same files, same rules, same save format)
  src/game/     GameHost (sim loop, commands, checkpoints), IndexedDB save slots, CameraRig
  src/render/   Three.js scene + presenters.ts (item stacks, customer crowd)
  src/ui/       React HUD, touch joystick, upgrades panel, styles from the design tokens
  test/         Vitest: shared parity fixtures + ported behaviour tests
```

Both clients load `shared/content` and `shared/assets` directly, so they cannot drift.

Content tooling (Phase 28): edit `shared/content/content-pack.json` against
`shared/schema/content-pack.schema.json` (`$schema` is already set). Validate before
commit with `cd web && npm run content:validate` (Ajv + cross-refs) and/or
`./gradlew :game-core:validateContent`. List species/recipes/quests with
`npm run content:catalog` or `./gradlew :game-core:validateContent -Pcatalog`.
CI (`.github/workflows/ci.yml`) runs both validators plus `:game-core:test` and web vitest.

## Build and run

Open the folder in Android Studio and sync. Then:

```
./gradlew :game-core:test          # simulation tests (fast, host JVM)
./gradlew :app:installDebug        # run on a device or emulator (OpenGL ES 3.0 required)
```

Web (Node 18+):

```
cd web
npm install
npm test            # engine tests, including Kotlin parity fixtures
npm run dev         # http://localhost:5173
npm run build       # static site in web/dist
```

Controls: joystick bottom-left on touch screens, or WASD / arrow keys; U opens upgrades.
Walk to the end of the pier to fish, drop fish on the teal pad left of the cutter,
collect portions from the pad on its right, stock the counter, and stand at the counter
to serve customers.

### When rules or content change

* Content edits (species / recipes / quests / …): keep `$schema` linked, then
  `cd web && npm run content:validate` and `./gradlew :game-core:validateContent`.
  Use `npm run content:catalog` to review the pack inventory.
* Layout changes: `python3 shared/tools/generate_blockout.py`
* Intentional balance/rule changes: `./gradlew :game-core:test -PrecordFixtures=true`,
  review the diff of `shared/fixtures/starter-line.json`, and commit it with the change.
  Then run `npm test` in `web/` and port the same change until it passes too.
* CI (`.github/workflows/ci.yml`) re-runs content validate + both test suites on every push/PR.

## Parity contract (Kotlin <-> TypeScript)

* Units: millimetres, ticks (20/s), integer coins. Integer division truncates toward zero
  (`Math.trunc`). Movement normalisation uses integer square root.
* Update order per tick: commands, movement, zone arrival, fishing, transfers, production,
  customers/payment, workers, progression, checkpoint.
* Iterate maps in sorted key order; customers and stations in list order.
* PRNG: Mulberry32, `nextBelow(n) = (u32 * n) >>> 32` (use BigInt or split multiply).
* Fishing only rolls species that fit in the bag, so a full bag never consumes a roll.
* Customers walk from `customerEntry` to their queue slot in ceil(distance / speed) ticks.
  Walkers do not reserve stock or lose patience. Leaving is presentation only.
* Saves are byte-identical across clients (same key order, compact JSON, CRC-32 of the
  state). Held joystick input is not saved: a reloaded player starts standing still.
* Keep `web/src/engine/systems.ts` line-comparable with the Kotlin systems.

### Save schema changes

Bump `SCHEMA_VERSION` in both engines, read the old shape in `readState(..., version)`,
copy a save in the old schema into `shared/fixtures/legacy/` and add a migration test on
both sides. Schema 2 added customer walking state.

## Status against the blueprint's production phases

Phase 1 (cross-platform spike) exists on both clients with grey-box art: a character,
water, a machine, HUD overlay, and save/load. Phase 2 ("core loop") rules exist in both
engines and are covered by shared fixtures. Item
stacks (bag, cutter input/output, counter) and walking customers are visible on both
clients. Quality presets (Phase 29) scale render cost; Phase 30 ships tutorial/empty-state
coaching, title funnel, store listing copy (`shared/store/listing.json`), save recovery
audit tests, and a release fixture pin (`shared/fixtures/RELEASE_PIN.json`). The sim stays
fixed at 20 Hz. Search for `TODO(blueprint` in the code.
